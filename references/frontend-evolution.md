# SuperPy 前端介面演進與設計方法

這是台美股兩類示範工作台的首版 UIUX 實務參考，包含介面演進的評估與可重用方法。完整操作契約維持在 [交易 UIUX 指南](trading-uiux.md)，OCO 專屬規則在 [OCO 參考](web-oco-application.md)。本篇補充設計決策的原因、反例與驗證，沒有附可直接啟動的前端模板。

## 素材範圍與適用性

素材最強的部分是本機交易工具的資訊架構、非同步操作、監控狀態與交易真相的對齊。網格以設定、規劃、委託與成本為核心；泡泡以持有部位與出場監控為核心。兩者剛好提供不同主用途下的設計取捨。

目前可先整理成台美股本機工作台的情境參考，是否改善開發或操作成效仍需測量。跨市場、遠端多人、手機原生操作、讀屏、長時間實際使用或整體可用性，仍需各自資料與驗證。桌面截圖、幾何檢查或一次瀏覽器流程，不能概括成所有使用者都更容易操作。

## 兩條演進路徑

| 工作台 | 演進方向 | 可重用的設計知識 |
| --- | --- | --- |
| 美股網格 | 基本設定精簡、進階風控分層；加入逐步精靈、草稿／模板與參數移轉；提供交接查核、完成收據、可搜尋說明與原介面展示 | 讓複雜設定逐步顯露，保留未完成工作，區分參數複製與交易狀態，讓完成結果可再查 |
| 台股泡泡／當沖監控 | 從操作面板延伸到泡泡、列表、委託及紀錄工作區；收起附加進場入口；整理浮動通知、模式與帳號；將登入完成與背景監控恢復分開 | 按主要任務分配畫面空間，用不同視圖讀同一份部位事實，讓監控狀態、失敗原因與下一步清楚可見 |

原成交後 OCO、逐原單 TradeUnit 與均價持倉週期有不同部位語意。視覺元件可以重用，資料模型與出場政策仍依該應用已確認規則。

## 十個可重用 pattern

下表的「建議驗收」是後續應檢查的條件，不是本輪已通過清單。「歷史摘要」指整理過往實作／檢查紀錄；原始收據沒有隨 skill 附送，讀者不能據此重建當時全部環境。「本篇歸納」表示建議，未聲稱歷史上已執行。

| 設計問題 | 建議做法與取捨 | 建議驗收 | 整理依據與限制 |
| --- | --- | --- | --- |
| 設定太多、入口不明顯 | 保留主操作，進階分層；必要時用精靈，提供直接編輯路徑；工具／說明入口使用可辨識文字 | 新增、編輯、錯誤修正與返回後都能續作，主要操作沒有被裁切 | 歷史摘要：網格精靈、編輯及基本／進階欄位操作檢查 |
| 開視窗或讀說明弄丟工作 | 表單草稿、選取、分頁、捲動與背景監控由原 owner 保留；說明使用靜態內容或獨立投影 | 打開／關閉後原輸入與選取相同，背景成交與監控仍能更新 | 歷史摘要：說明頁與背景成交、草稿續作的瀏覽器情境 |
| 不知道非同步工作進行到哪 | 立即顯示已接收，逐步呈現登入／查核階段；busy 限制重複送出，保留原操作 ID 查詢 | 慢回覆、錯誤、UI 逾時及後到成功都可定位原要求，不因逾時再送交易 | 歷史摘要：登入串流、命令進度；本篇歸納：對任意操作套用完整驗收 |
| 綠燈被誤讀為自動出場可用 | 分開本機引擎、券商、帳號、行情、對帳與自動效果資格；用文字解釋有效範圍 | 已登入但未核對、行情過期與禁止送單都不呈現為正常自動監控 | 歷史摘要：後端失聯快取重畫、首次讀取失敗及監控恢復顯示 |
| 恢復／錯誤訊息一直佔畫面 | 一般進度可收起；影響主用途的停用狀態持續可見，附具體失敗步驟與下一步 | 關閉通知不會改交易狀態；輪詢不反覆彈同一提示，重大停用仍可辨識 | 歷史摘要：收起提示、跨輪詢與恢復失敗的場景 |
| 泡泡吸睛卻難精確查帳 | 泡泡表達部位、損益與動態，列表提供數字、排序與操作；從同一快照投影 | 兩種視圖的部位 ID、餘量與保護狀態一致；記錄缺漏或換帳本不播放成交出場 | 歷史實作摘要：兩種視圖及已確認出場動畫；本篇歸納：完整跨視圖數值一致性驗收 |
| 動畫造成捲軸閃爍或難點選 | 穩定配置與容器尺寸；讓動效表達事件，提供暫停／減少動態方式 | 大量部位、小視窗、縮放、hover／焦點與停止動效時仍可操作 | 歷史摘要：多部位容器／捲動；本篇歸納：減少動態及完整輸入方式驗收 |
| 行情看似更新卻不可用 | 同商品／交易別顯示來源時間及有效性，區分參考價、成交、過期、斷線 | 缺少零股行情時不借整張；後端失聯時快取重畫仍顯示無法確認 | 歷史摘要：整零股行情卡片與合成失聯情境，非正式行情驗收 |
| 交易確認窗看不出影響 | 顯示帳戶、模式、單位、作用範圍、原單／預留與前後差異；完成後保留收據 | 預覽後狀態變動會使舊確認失效；未知結果可查原收據，確認不重複提交 | 歷史摘要：部位交接／預覽失效及回覆遺失；本篇歸納：其他操作的擴充 |
| 展示與實際工具越走越遠 | 共用維護中的原介面與控制項，以隔離假傳輸驅動；旁白連到目前步驟 | 真實 DOM 事件與顯示流程可重播；展示不能寫真實帳本或取得交易能力 | 歷史摘要：原介面放映、半速與互動暫停；不證明真實交易可用 |

這些是選用方法。固定工作區適合持續監控桌面；短查詢工具、其他策略或手機介面應依其用途重新安排，不必照搬工作台配置、字級與顏色。

## 兩個值得保留的前後案例

以下是設計變更紀錄的摘要，未量測使用者成功率、操作時間或整體使用成效。

**概念展示改為原介面展示。** 原先獨立動畫可以解釋故事，卻無法證明登入、精靈、核對及成交頁的操作。後續改由原 UI 加隔離假傳輸運作，並提供半速、浮動旁白及誤操作時暫停／返回。可抽出的知識是：展示的主張若包含操作流程，測試就要經過該流程。

**登入關窗與監控恢復拆開。** 完成登入／選帳即返回主工作台，背景繼續核對部位與原單。主畫面持續顯示是否真正開始自動出場；背景失敗留在工作台指明原因。這能讓登入交互完成，同時保留監控的獨立完成條件。

## 最小驗證方式

先由受影響操作挑場景，不為純 CSS 修改重跑所有交易測試。常見檢查包括：

- 真實控制項：點選、輸入、確認、返回及下一次輪詢後仍符合預期。
- 慢／錯誤資料：晚到預覽不覆蓋新輸入，過期快取不偽裝有效狀態。
- 尺寸與輸入方式：目標桌面尺寸、縮放、鍵盤、焦點、dialog 與長資料捲動。
- 跨流程延續：讀說明、切泡泡／列表、收起通知或離開展示後，既有工作仍在。
- 交易隔離：UI 展示與 FakeSDK 測試保留其證據層級，不替真實券商驗收背書。

歷史演進有各版瀏覽器與幾何證據；本篇整理沒有重新執行原工作台的全部 UI 測試。後續若要擴充成完整 UIUX 大全，優先補三個可重播前端案例：設定與草稿續作、登入至監控恢復、泡泡／列表／委託的同一事實投影。先驗證跨流程結果，再擴充元件或視覺模板。
