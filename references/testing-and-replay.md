# 測試、重播與 skill 成效評估

選能推翻當前主張的最低測試層級。實作、示範、真實觀察與發布，各自需要對應證據；本篇不建立每次修改都要完整跑完的流程。

## 先說清楚是哪種證據

| 來源／執行面 | 能支持的範圍 | 未直接支持 |
| --- | --- | --- |
| 靜態 API／程式查核 | 名稱、欄位契約、呼叫與 guard 結構 | 執行時序與實際服務可用 |
| 純合成事件與本機測試 | 被供應的正常、邊界與故障分支 | 真實 SDK payload 或撮合 |
| SDK 測試環境 | 該環境的介面與回報觀察 | 正式帳戶與市場行為相同 |
| 去識別化真實事件重播 | 目標程式如何解讀該批真實格式 | 新的券商要求會被受理 |
| 正式環境唯讀 | 已觀察的登入、行情、回報與庫存可見性 | 真實送改撤單及未平倉保護 |
| 有人觀察的受控實單 | 選定帳戶、商品、時段、規模下的真實效果 | 整日、跨日或無人值守營運 |

例如當沖工作台的歷史材料包含真實唯讀接續與重登觀察，以及 FakeSDK 的停利、停損及尾盤出清。這兩者分別保存來源；不能把它們合成「正式出場已驗證」。

## 三個重播邊界

1. **原始 payload 邊界**：檢查 SDK adapter 的欄位、單位、資料分組、callback 世代。
2. **正規化事件邊界**：檢查帳本、策略、去重、餘量與恢復。首版三個 Python 範例位於這層。
3. **生命週期邊界**：從登入／訂閱、同步 return、callback、查單／成交／庫存走到下一次決策；券商效果仍由注入 transport 取代。

同一案例可有不同高度的輸入，但結果要標示真正走過的交接點。內部 position 或 UI snapshot 不能冒充原始券商回報；相同 raw object 上未更新的五檔／成交欄位，也不能混成一筆新成交。

## 一個有用情境需要什麼

- 使用目的與已確認策略，前置狀態、商品／交易別及數量單位。
- 同步返回、callback、後續查詢的受控時間線；包含缺席、重複、延遲或亂序。
- 可關聯的 session、generation、原單、execution 與操作 ID。
- 應保留的事實、允許與禁止的效果，以及正向續接條件。
- 來源種類、SDK／候選版本、fixture 身分、命令、結果及未覆蓋範圍。

欄位數量依斷言需要決定，不必為小型單元測試先建大型錄製平台。共享規格可以重用，但不讓公開 skill 依賴未公開的本機路徑或私人資料。

## 對照要能分辨錯誤

安全可重現的缺陷，優先保留修改前失敗與修改後通過。新寫的教學模型只能宣稱它自己的反例檢查；不能稱為已跑過歷史應用的 fail-first。

測試同時包含允許繼續的情況。例如 reference 不可用時保留部位而不送出場，條件齊備後能產生計畫；撤單終態先到時等待最後成交，補齊後按正確餘量繼續。永遠阻擋所有操作不足以驗證自動化工具。

## 首版固定前後測

題組為 [questions.json](../evals/questions.json)，評分器為 [score.py](../evals/score.py)。它評量十個具體開發情境的結構化決策，包括三個案例、命令效果確定性、策略保留、guard 目的、原介面展示、完整恢復、小腳本的非觸發及成交衝突隔離。

比較方法：

1. 修改前凍結題組與判準；舊、新 skill 分別提供給兩個互不看答案的同模型／同強度執行者。
2. 執行者由 `SKILL.md` 自然選讀參考，不先收到應讀清單、標準答案或評分器。
3. 保存原始輸出、實際讀取參考、skill／題組身分；檢查每個回答的理由是否與結構化決策一致。
4. 依具體行為決策評分，另列個案差異、非觸發控制與證據限制；不以關鍵字、標題或文件變長評分。

```console
python -B -X utf8 evals/score.py path-to-response.json
```

題組本身會提示待判斷欄位，且只有一組配對試驗；這會限制外推能力。若新舊同分，結論是這組題目未量到提升，不改題、不重抽直到看到差距。題目也未證明自然語言提示下的完整程式生成、長期可靠度或 live trading。

測試輸出與已讀檔案是可核對證據，不等於無遺漏的工具追蹤。現有批次的實際結果及任何有效性缺口見 [評估紀錄](../evals/evaluation.md)。

v1 自由文字狀態欄位仍使用固定別名診斷，必須搭配語意判讀，不能直接將名稱比對分數視為工程正確率。後續評測快照排除 `evals/` 與既有答案；保留受測快照身分及最終版差異。

## 串接工程工作流的待執行案例

[integration-workflow-cases.json](../evals/integration-workflow-cases.json) 提供十二個情境種子與可觀察決策判準，涵蓋能力盤點、未知效果、恢復、工具鏈與交付，以及小查詢、局部修補、工具缺席和歷史授權的非觸發控制。它們目前全部是 `NOT_RUN`，不是已完成的行為評測，也沒有可直接執行的應用程式 fixture。

使用時，先補齊能區分錯誤的最小程式或 payload，凍結受測候選與題目。將使用者請求與必要原始資料提供給執行者，保留判準供另行評分；記錄實際選讀、工具操作及可執行結果，不先指定應讀參考。這些情境與指引整理自同類經驗，不能單靠同源案例證明外推能力；評估泛化時需另取未用於編寫指引的任務。既有十題的歷史分數仍只對應原受測版本。
