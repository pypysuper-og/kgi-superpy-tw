# SuperPy 串接開發實務：台美股首版

這份實務篇把 API 契約、狀態協作、故障案例與可執行離線檢查連在一起。案例主要來自台美股工作台的開發、隔離重現與諮詢經驗，尚未形成期貨實務案例庫；API 的適用版本與查證方式見 [來源與驗證](source-verification.md)。

## 如何閱讀案例

每個案例都交代使用目的、假設、狀態與責任、事件順序、錯誤模式、處理方式、離線命令及證據限制。範例中的事件與商品全部是合成資料；數量在示範模型邊界已正規化為整數股。正式 SDK adapter 必須另行驗證原始數量、單號、帳戶、交易別與時區。

三個案例的可執行模型在 [practical_cases.py](../examples/practical_cases.py)，反例檢查在 [test_practical_cases.py](../examples/test_practical_cases.py)。它們不匯入 SDK、不連網、不呼叫券商，示範的是應用程式的特定交接點。原工作台的部署與真實券商能力，仍需由各應用版本自己的證據支持。

## 保留策略差異

| 設計 | 部位身分與成本 | 使用時要先確認 |
| --- | --- | --- |
| 逐筆 unit／OCO | 每筆進場意圖及其成交、出場各自關聯 | 部分成交如何保護，同商品多 unit 如何保留可賣量 |
| 依進場 OrderNo 分筆 | 同原單的分批成交更新該單成本 | 不同原單不因同商品、同方向就合併 |
| 同方向持倉週期 | 同帳戶／商品／方向合併餘倉均價，全平後另開新輪 | 反向抵銷、外部成交與晚到原輪成交如何歸屬 |

以上都是可成立的產品選擇。取用工程做法時保留目前已確認的策略；改變成本或部位政策，需要當下開發者決定。參考程式的測試不能替其他程式的修改版背書。
