# SuperPy 開發的人機協作與實務工程夥伴

這份指南把交易工具開發過程中反覆出現的有效追問，提煉成 agent 可自然使用的工程判斷。它來自具體需求修正與驗收互動的一般化整理；以下提示都是重新撰寫的教學情境，不是私密對話逐字稿，也不是人格評估。

## 工程夥伴如何在背景運作

在重要的 SuperPy 設計、排錯或驗收判斷中，讓目前 agent 多看一眼功能目的、必要假設、狀態責任、使用路徑與證據。這個「夥伴」是一組內建思考線索，在同一次工作中運作，不另開模型或背景程序，也不代表某位開發者正在場外審核或授權。

平常直接完成已明確的工作。有具體證據顯示方向會走偏時，才提出一個短而有用的建議，交代影響及下一個可驗證動作；需要使用者選擇的策略與取捨，保留給當下開發者。

觸發例：安全 guard 擋到主用途、登入成功卻沒恢復監控、展示沒有走原控制項、同一事實在 UI 與帳本互相矛盾、參考策略被直接套入客戶需求。非觸發例：單一 API 查詢、文字修正、已明確的局部 CSS 調整。這份指南不建立固定審查輪次、WAL、狀態盤點或重問許可的要求。

要移動或放寬既有 guard，先查明它保護的目的、缺資料時已確認的政策、行為差異與目前授權。有些產品刻意在 reference 失效時停止整個觀察流程，應保留這項已確認決定。既有授權已涵蓋且工程事實明確的修正可直接完成；主用途、合規要求或效果範圍仍未定時，才把具體取捨交給開發者。

## 八種可重用的判斷方式

| 思路 | 從互動觀察到的修正方向 | agent 可以自然提出的問題／下一步 |
| --- | --- | --- |
| 由使用結果定義完成 | 自動出場工具應在核對後真的接回監控 | 「下一筆有效行情進來，這個部位會繼續被評估嗎？」沿流程驗證到下一次決策 |
| 追問機制的必要性 | 不因程式已有日期檢查或對帳，就假定它都必要 | 「這個欄位能證明它要保護的結果嗎？」先查契約，再調整 guard 的位置或依據 |
| 分開事實與效果權限 | 成交存在與允許自動出場分開呈現 | 保存已確認成交，資格不足時顯示僅監控，將 guard 放到真正依賴它的效果前 |
| 用實際入口驗證 | 原介面操作展示應使用同一套控制項與事件 | 把假資料接到既有傳輸邊界，走實際表單／精靈／確認，不以概念畫面證明操作完成 |
| 看轉移帶來的功能改變 | 狀態盤點的目的在優化與排錯 | 說明改動前後誰會多做、少做或正確繼續什麼；保留合理分工也是有效結果 |
| 把異常限制在實際範圍 | 可定位商品的問題不拖累其他已確認部位 | 追蹤預留量與 effect guard，證明局部隔離一路到 SDK 邊界與 UI |
| 讓狀態有可理解的下一步 | 失敗應指出具體步驟，不能看似可用卻不會自動出場 | 顯示「目前不會自動出場」、失敗步驟與重試／接手入口；一般提示可收起 |
| 把經驗交給下一次協作 | 提供可重播資料、必要開發紀錄及容易採用的 prompt | 用版本、關鍵決策、命令與結果保留最小可追查脈絡；依任務需要選材料 |

這些是可觀察的協作方法，不是所有專案固定答案。例如均價持倉週期與逐單分筆都可成立；使用者已確認其中一種時，工程夥伴應維護該意圖。

## 三個背景提醒的範例

**監控工具在 reference 失效時停止讀回報：**

> 若已確認主用途是持續觀察外部成交，且缺資料政策只停用新的自動交易，這個檢查可放到出場資格處。這會讓 reference 缺漏時仍讀回報並入帳；我先核對既有政策與授權，未定的產品取捨再請你決定。

**恢復只驗到登入成功：**

> 還需要確認原部位、callback、行情與策略評估已接回。我沿原監控流程補一個續接案例，保留使用者停止與剩餘額度。

**小型查詢被設計成整套工作台：**

> 目前需求用已選帳的公開查詢方法即可完成。先交付簡短函式與對應契約，等有持久監控或多人隔離需求時再增加結構。

這些提醒的價值在於改變下一個有用動作；不需要每回合把內部檢查全部念給使用者。

## 在串接任務中使用跨專案經驗

需求、資料鏈、除錯、測試或交付出現具體疑問時，按需閱讀 [串接工程判斷](integration-engineering-workflow.md)。先查既有平台能力，再沿資料語意、時效與實際 consumer 找缺口；檢查機制是否真的必要，並把未確認效果限制在相依操作。原始碼、套件、安裝實例、運行觀察與公開版本各自需要對應證據。

這些經驗幫助完成目前的 SuperPy 任務，不自動擴大 skill 的觸發範圍。工具或其他 skills 只有在確實有幫助且可用時才選用；沿用專案既有環境、授權、策略與停止條件。歷史上的模型偏好、正式操作許可、強制流程與清理提案不成為新任務的預設規則。

## 人與 agent 的決策分工

開發者決定主用途、納管範圍、部位政策、曝險及真實操作授權。Agent 自行查證 API、欄位與程式路徑，完成既有授權內的實作及聚焦驗證，並保留證據限制。

只有尚未定案、會改變產品使用方式或外部效果的重要決定才詢問。若已有自動恢復協議，恢復符合條件的原監控；若對帳身分仍需人工配對，停在那個配對點。技術上可查證的事實不要全部丟回使用者，也不能把建議預設值當成已同意。

## 可直接採用的協作 prompt

```text
請使用 SuperPy skill，幫我完成［需求］。
主要使用結果是［具體結果］，保留［既有策略／介面／資料］。
先查明 API 與實際程式路徑，在已授權範圍內完成實作和必要驗證。
遇到會改變策略或使用方式的未定決策，給我簡短選項；工程事實請自行查證。
請在重要判斷中留意 guard 的目的、事實與效果權限、恢復後的實際功能，
用最小反例驗證有疑慮的交接點，最後交代改變、證據及限制。
本次券商操作範圍是［不連線／唯讀／另外明確授權的範圍］。
```

## 如何確認這個夥伴有幫助

看 agent 是否在具體情境做出更好的決定：保留已確認部位、質疑錯誤 proxy、接回真實使用流程、維持策略差異，同時不替小需求增加流程。評估方法見 [固定題組與證據限制](testing-and-replay.md)。不能僅因回覆更像某個人的語氣，就宣稱工程品質提升。
